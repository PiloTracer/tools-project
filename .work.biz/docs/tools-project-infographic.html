Four pillars, one app

01

Project management

Projects get a short key (PROJ), every task and ticket gets a ref (PROJ-123, UMB-T-7). Kanban boards, ticket triage queue, threaded activity feed with @mentions, components, inbox, watches.

02

CRM pipeline → delivery

9 validated stages. On won, promote prospect → client in one click. Add contacts, link client to project, grant access roles.

target→ connected→ engaged→ call→ proposal→ negotiating→ won / lost
03

Attach anything to anything

Screenshot on a ticket. PDF contract on a task. Log on an activity reply. Content-sniffed server-side, capped (25 MiB/file + per-project quotas), auto-purged on retention. The file lives next to the thing it was about.

04

GitHub + auto-association

Link multiple repos. PATs encrypted at rest (Fernet). Commits surface as activity cards. And — commits auto-link to tasks, including when an AI agent does the coding.

The headline: commits auto-link to tasks

Every task/ticket has a structured ref (PROJ-456). A prepare-commit-msg git hook reads the branch name and prepends the ref to the commit subject — automatically. When the GitHub poller pulls the commit back in, a normalizer writes a row into commit_subject_refs linking the commit to the task.

Works identically for a human typing git commit -m and for an AI coding agent running git commit programmatically. This app was built using .ai (Agent OS), .ai.ui (UI Design OS), and .ai.biz (Business OS) — every agent commit flows through the same hook and lands on the right task.

# branch: feature/PROJ-456-login $ git commit -m "Add login form with email validation" # → commit subject becomes: PROJ-456: Add login form with email validation # → on GitHub sync, auto-linked to task PROJ-456
