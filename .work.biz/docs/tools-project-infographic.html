What it replaces

Task tracker

Kanban, references, components, threaded comments — no Jira seat.

CRM

Prospect pipeline, client records, contacts, portal — no HubSpot bill.

Ticket system

Triage queue, attachments, status tracking — no Zendesk tier.

Code-to-task linking

Project management

Tasks & tickets on one spine

  • Projects with custom keys (e.g. PROJ, UMB) — auto-generated refs like PROJ-123
  • Drag-and-drop Kanban — todo, in-progress, review, done
  • Support ticket queue with triage workflow and assignment
  • Components to organize work within a project
  • Threaded activity feed per project — mentions, system events, commit cards
  • Inbox + watches — central notifications without being on every email thread

Attach anything. To anything.

  • Screenshot on a ticket · contract PDF on a task · log on an activity reply
  • Server-side content-type sniffing — a renamed .png is still treated as text
  • Per-file cap: 25 MiB
  • Per-project caps: file count + byte total (configurable)
  • Automatic retention purge (configurable retention days)

GitHub integration — respects how engineers actually work

The integration itself

  • Link any number of repositories per project via PAT
  • PATs encrypted at rest (Fernet symmetric encryption)
  • Never returned by any API · never written to logs
  • Background poller — configurable interval (default 5 min)
  • Backfill action — re-sync last 365 days
  • Verification stays on GitHub via clickable html_url — we link out, we do not render diffs in-app

Auto-association — the surprising headline

Commits get linked to tasks automatically — including when an AI agent does the coding.

  • Every task/ticket has a structured ref (PROJ-456, UMB-T-7)
  • prepare-commit-msg git hook reads branch name (or session file) and prepends the ref to the commit subject
  • When the poller pulls the commit back, a normalizer parses the subject and writes a row into commit_subject_refs
  • The task lights up with a clickable SHA — automatically
  • Works identically for humans and AI coding agents
# branch: feature/PROJ-456-login $ git commit -m "Add login form with email validation" # → commit subject becomes: PROJ-456: Add login form with email validation # → on GitHub sync, auto-linked to task PROJ-456

The dual audience this is for

Consultancies & agencies

Currently paying for a task tracker, a CRM, and a GitHub-friendly wiki — wanting one bill and one login instead.

Engineering teams that sell

The sales motion and the delivery motion share staff — tools should share a brain.

AI-agent teams

The moment an agent can run git commit, you need commit messages that auto-link to tracked work. This is the default, not the afterthought.
