# Cross-App Reference — Feature SPEC

**Status:** Approved
**Owner:** Engineering
**Related plans:** `proposal_tools_project_ecosystem_hub` (Modification 3)

## 1. Purpose
Generalize the existing `commit_subject_refs` table into `external_refs` with a `source_app` column so any satellite app (CompanyBrain, OpsBoard, SignFlow, LedgerLite) can link references to tools-project entities. This enables rich cross-app activity cards in the existing Inbox/Activity Feed.

## 2. In scope / Out of scope
**In scope:**
- Schema: rename `commit_subject_refs` → `external_refs`, add `source_app VARCHAR(30)`, add `external_url TEXT`, add `label VARCHAR(200)`
- Model: new `ExternalRef` model matching new schema
- Router: `GET/POST/DELETE /v1/projects/{id}/external-refs` (generic cross-app CRUD)
- Backfill existing `commit_subject_refs` rows with `source_app='github'`
- Activity auto-create when external ref is added (reuses existing pattern)

**Out of scope:**
- Front-end activity card rendering changes (reuses existing `ActivityClient.tsx` pattern)
- Migration of the old `commit_subject_refs` router (keep both during transition)

## 3. Behavioural spec
R1 — `POST /v1/projects/{id}/external-refs` creates a ref with `{ source_app, external_id, external_url, label, subject_type, subject_id }`.

R2 — `GET /v1/projects/{id}/external-refs?subject_type=&subject_id=` lists refs for a given subject.

R3 — `DELETE /v1/projects/{id}/external-refs/{id}` removes a ref.

R4 — Existing `commit_subject_refs` data is preserved with `source_app='github'` backfill.

R5 — Existing `github_commit` activity rendering continues working unchanged.

## 4. Data model
Schema migration in `sql/schema_changes.sql`: add columns to `commit_subject_refs`, backfill, then create `external_refs` view or rename.

## 5. API
`GET/POST/DELETE /v1/projects/{id}/external-refs`
