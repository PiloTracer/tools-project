# Platform Whoami — Feature SPEC

**Status:** Approved
**Owner:** Engineering
**ADRs referenced:** ADR-0001 (client-contact model), ADR-0002 (backend stack)
**Related plans:** `proposal_tools_project_ecosystem_hub` (Modification 2)

## 1. Purpose

A single lightweight endpoint that takes a tools-project personal API key (or Bearer JWT) and returns the caller's identity plus the list of client companies they can act on behalf of. This is the shared identity layer for the satellite app ecosystem: CompanyBrain, OpsBoard, SignFlow, and LedgerLite use this instead of each building their own login/signup.

## 2. In scope / Out of scope

**In scope:**
- `GET /v1/platform/whoami` endpoint
- Auth via `require_agent_or_user` (X-Api-Key or Bearer JWT — reuses shipped code)
- Returns `{ user, companies: [{ client_id, name, role }] }`
- Companies derived from `client_contacts` where `user_id` matches the authenticated user
- Response includes `user.id`, `user.email`, `user.display_name`

**Out of scope:**
- Full OAuth2 Authorization Server (authorize/token/consent endpoints — explicitly deferred)
- User registration or signup (satellite apps assume user already has a `tools-project` account)
- Permission scopes beyond what `client_contacts.role` provides
- Rate limiting specific to this endpoint (inherits global rate limiter)

## 3. Domain language

| Term | Definition |
|------|------------|
| Whoami | An endpoint that tells a caller who they are and which companies they represent |
| Platform identity | Shared identity resolution across the ecosystem — not a full SSO provider |

## 4. Behavioural spec

R1 — `GET /v1/platform/whoami` requires authentication via `require_agent_or_user` (X-Api-Key header or Bearer JWT).

R2 — Returns `401` for unauthenticated requests.

R3 — Returns `{ user: { id, email, display_name }, companies: [] }` when the authenticated user has no client contacts.

R4 — Returns populated `companies` array with `{ client_id, name, role }` for each `ClientContact` where `user_id` matches.

R5 — The `role` field is the raw value from `client_contacts.role` (e.g. `"contact"`, `"contact_admin"`).

R6 — Runtime: fast single-query lookup (<50ms). No N+1.

## 5. Data model

No new tables. Reads from existing:
- `users` (via `require_agent_or_user` auth)
- `client_contacts` (filtered by `user_id`)
- `clients` (joined for `name`)

## 6. APIs

### `GET /v1/platform/whoami`

**Headers:**
- `Authorization: Bearer <jwt>` or `X-Api-Key: <personal_api_key>`

**Response `200`:**
```json
{
  "user": {
    "id": "uuid",
    "email": "user@example.com",
    "display_name": "Jane Doe"
  },
  "companies": [
    {
      "client_id": "uuid",
      "name": "Acme Corp",
      "role": "contact_admin"
    }
  ]
}
```

**Response `401`:**
```json
{ "detail": "Not authenticated" }
```

## 7. Invariants

- The response is always consistent within a single API key's lifetime — a user's company membership changes only when `client_contacts` entries are added/removed.

## 8. Error model

| Code | Condition | Behaviour |
|------|-----------|-----------|
| 401 | Missing or invalid credentials | Standard `require_agent_or_user` error |
| 500 | Unexpected DB error | Logged; generic error returned |

## 9. Observability

- One access log line per call (inherited from existing `request_id_middleware` in main.py)
- No additional instrumentation needed

## 10. Security and privacy

- Reuses existing `require_agent_or_user` auth — same security bar as the Agent Query API
- Returns only `client.name` (public company name) and `client_contacts.role` — no sensitive data
- No PII beyond what the caller already knows (their own email and display name)

## 11. Test plan

| Test | Scope | Method |
|------|-------|--------|
| Valid API key returns user + companies | Integration | POST key creation → GET whoami → assert user + company fields |
| Bearer JWT returns same shape | Integration | Use login flow → GET whoami → assert shape |
| Unauthenticated returns 401 | Unit | GET without auth headers → assert 401 |
| No client contacts returns empty companies | Integration | Use user without contacts → assert companies=[] |

## 12. Rollout and rollback

- Additive only — no existing code changes. Rollback: remove router import from `main.py`.
- No feature flag needed.

## 13. Open questions

- Should the endpoint live at `/v1/platform/whoami` or `/v1/me/whoami`? **Proposal says platform** to signal ecosystem scope. The existing `/v1/me/` prefix is for tools-project's own user features. `/v1/platform/` is the right prefix for cross-app identity.
