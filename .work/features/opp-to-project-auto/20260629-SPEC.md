## 1. Purpose

When a prospect reaches `won` and is promoted to a client, automatically scaffold a project with onboarding tasks, client link, and access grants — eliminating the manual handoff gap between sales closing a deal and the delivery team starting work.

---

## 2. In scope / Out of scope

### In scope
- Auto-create a project when a prospect is promoted to client
- Project named `"{company_name} Onboarding"` with descriptive slug
- Link the client to the project via `project_clients`
- Create hardcoded onboarding tasks (welcome, kickoff, setup, first milestone)
- Write activity entries recording the conversion event
- Return project info in the promotion response
- Frontend: show "View project" link in the promotion success dialog

### Out of scope
- Configurable task templates (hardcoded default for MVP)
- Per-user or per-organization task templates
- External notifications (email) on project creation
- Auto-assign tasks to team members (created unassigned)
- Billing/invoicing integration

| Term | Definition |

| Onboarding project | Auto-created project scaffolded when a prospect becomes a client |

## 4. Behavioural spec

### R1: Auto-scaffold on promotion
When `promote_prospect_to_client()` is called (via stage transition to `won` or direct promote endpoint), if the prospect has no existing client record, after creating the `Client`:
1. Create a `Project` named `"{company_name} Onboarding"` with slug `"{slug}-onboarding"`
2. Create a `ProjectMember` with role `owner` for the promoting user
3. Link the new client via `project_clients`
4. Create hardcoded onboarding tasks (see R2)
5. Write an activity entry on the new project with kind `transition` describing the conversion

### R2: Onboarding task template
The following tasks are created on the new project:
1. "Welcome and introduction call" — set up kickoff meeting
2. "Contract and paperwork" — finalize signed agreement
3. "Deposit or initial payment" — process first invoice
4. "Repository and tooling setup" — create repos, configure CI
5. "Communication channel setup" — Slack/Discord channel, shared drive
6. "First milestone planning" — define sprint 1 scope
7. "Stakeholder introductions" — connect team with client contacts

### R3: Client access
If the promoted prospect has contacts with linked `user_id` accounts, auto-grant `contribute` access to the new project for each contact.

### R4: Activity recording
Write an activity on the new project: `"{user} converted {prospect_company} to a client and created this onboarding project"` with `kind=transition`, `is_internal=true`.

---

## 5. Data model

No new tables. Uses existing:
- `projects` — auto-created
- `project_members` — auto-created for promoting user
- `project_clients` — link to new client
- `project_client_access` — grants for contacts with user accounts
- `tasks` — onboarding task list
- `activities` — conversion event

---

## 6. APIs

Existing endpoints modified:
- `PATCH /v1/prospects/{id}/stage` — when transitioning to `won`, returns project info in response
- `POST /v1/prospects/{id}/promote` — returns project info

---

## 7. Invariants

- Promotion must still validate that prospect is in `won` stage
- Auto-scaffold only happens once per prospect
- If a project already exists for this prospect's client, do not create a duplicate
- All DDL is idempotent

---

## 8. Error model

| Condition | HTTP | Detail |
|-----------|------|--------|
| Prospect already has a client with a project | 409 | "Client already has an onboarding project" |
| Prospect not in `won` stage | 422 | "Prospect must be in 'won' stage to promote" |

---

## 9. Observability

- Activity log records the conversion event
- No new metrics for MVP

---

## 10. Security and privacy

- Only internal team members can trigger promotion (already gated by auth)
- Project is created with owner = promoting user; other team members can be added manually later

---

## 11. Test plan

| Layer | What to test |
|-------|-------------|
| Unit | `promote_prospect_to_client` creates project + tasks + activity |
| Integration | PATCH stage to `won` returns project info; `/promote` endpoint creates project |
| Manual | Full flow: create prospect → advance to won → verify project + tasks created |

---

## 12. Rollout and rollback

No feature flag — additive change. Existing clients without auto-scaffold projects are unaffected. To roll back, remove the project creation call from the promotion service.
