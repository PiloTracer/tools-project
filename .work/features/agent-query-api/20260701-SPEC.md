## 1. Purpose

Provide a read-only API surface + MCP server so the local coding agent (opencode) can query project context — tasks, tickets, clients, prospects, GitHub refs — without requiring manual copy-paste or browser navigation. Enables agent workflows like:

- Building commit messages with ticket URLs and refs
- Reading full project context (tasks, tickets, description, health) in one call
- Checking pending tasks and verifying against local HANDOFF/NEXT context

---

## 2. In scope / Out of scope

### In scope
- Aggregation endpoints under `/v1/agent/` that bundle related data into LLM-friendly flat JSON
- API key authentication for agent access (optional shared secret)
- Python MCP server at `.opencode/mcp/project-mcp/` that wraps the aggregation endpoints
- Registration of the MCP server in `opencode.json`
- Documentation with usage examples

### Out of scope
- Write/mutate endpoints (all agent endpoints are read-only)
- Per-user rate limiting (uses existing auth)
- Web UI changes
- Real-time or SSE endpoints
- Pagination for agent queries (reasonable limits applied server-side)

## 4. Behavioural spec

### R1: Aggregation endpoints
The API exposes read-only aggregation endpoints under `/v1/agent/`:

- `GET /v1/agent/projects` — list all projects with summary stats (task/ticket counts)
- `GET /v1/agent/projects/{id}/context` — full project context: details, tasks, tickets, members, linked clients, health
- `GET /v1/agent/tickets` — list tickets across all accessible projects, with optional ref filter
- `GET /v1/agent/tasks` — list tasks across all accessible projects, with optional ref filter
- `GET /v1/agent/search?q=` — unified search across projects/tasks/tickets/clients/prospects

### R2: Agent authentication
Agent endpoints accept either:
- Standard Bearer JWT (existing `get_current_user`), OR
- `X-Api-Key` header matching `AGENT_API_KEY` from Settings

When using API key auth, the user context defaults to a superuser agent scope for full read access.

### R3: MCP server
A Python MCP server at `.opencode/mcp/project-mcp/` that:
- Reads `AGENT_API_KEY` from `.env` or environment
- Connects to the local API at `http://localhost:8300`
- Exposes MCP tools: `get_project_context`, `get_ticket_info`, `get_task_info`, `search_entities`, `list_projects`
- Each tool returns structured JSON

### R4: opencode integration
The MCP server is registered in `opencode.json` under `mcp` so the coding agent can invoke its tools.

## 5. Data model

No new tables. Uses existing:
- `projects` — project details
- `tasks` — task list for project context
- `tickets` — ticket list for project context
- `project_members` — member info
- `clients` — linked client info
- `prospects` — prospect info
- `github_commits`, `commit_subject_refs` — GitHub commit links

---

## 6. APIs

### New endpoints

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| GET | `/v1/agent/projects` | Bearer or ApiKey | List all projects with summary stats |
| GET | `/v1/agent/projects/{id}/context` | Bearer or ApiKey | Full project context |
| GET | `/v1/agent/tickets` | Bearer or ApiKey | List tickets (filterable by ref) |
| GET | `/v1/agent/tasks` | Bearer or ApiKey | List tasks (filterable by ref) |
| GET | `/v1/agent/search` | Bearer or ApiKey | Unified search |

### Response format

All responses return flat JSON with `{ "ok": true, "data": ... }` envelope for consistent agent parsing.

### Existing endpoints reused
- `GET /v1/projects/{id}/github/refs` — commit-subject refs (already exists)
- `GET /v1/projects/{id}/github/task-registry` — task registry JSON (already exists)
- `GET /v1/projects/{id}/github/readiness` — readiness checklist (already exists)

---

## 7. Invariants

- All agent endpoints are read-only — no mutations
- API key auth never allows write access
- MCP server connects to localhost only (no external exposure)
- Default limits applied to prevent large responses

---

## 8. Error model

| Condition | HTTP | Detail |
|-----------|------|--------|
| Invalid/expired API key | 401 | "Invalid agent API key" |
| Project not found | 404 | "Project not found" |
| No API key configured and no Bearer token | 401 | "Not authenticated" |

---

## 9. Observability

- Request logging via existing middleware (X-Request-Id)
- Agent requests tagged with `agent: true` in logs

---

## 10. Security and privacy

- API key is optional and read-only
- API key is stored in `.env` — never committed
- MCP server only listens on localhost
- No new PII exposure beyond what existing endpoints return
