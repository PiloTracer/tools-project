## 1. Purpose

Provide a unified dashboard that combines CRM client data with project delivery metrics into a single health overview. Account managers and leadership can see at a glance how every client is doing — task progress, ticket backlog, engagement recency — without switching between screens.

---

## 2. In scope / Out of scope

### In scope
- Backend endpoint computing health metrics per client
- Health score: green (healthy), yellow (at-risk), red (critical)
- Metrics: task completion rate, ticket backlog count, days since last activity, days since last project update
- Dashboard page at `/clients` with health cards
- Click-through to client detail and linked projects
- Accessible to internal team members (project members + admin)

### Out of scope
- Client-visible health dashboard (internal only for MVP)
- Historical trend data / health over time
- Email alerts on health changes
- Revenue/profitability metrics
- Customizable health thresholds

---

## 3. Domain language

| Term | Definition |
|------|------------|
| Health score | Computed rating: green (≥80%), yellow (50-79%), red (<50%) |
| Task completion rate | `completed / (completed + open + in_progress)` tasks across all linked projects |
| Ticket backlog | Open/unresolved tickets across all linked projects |
| Activity recency | Days since any activity on any linked project |

---

## 4. Behavioural spec

### R1: Health endpoint
`GET /v1/clients/health` returns a list of all clients with computed health metrics.

### R2: Health scoring
Score is computed as weighted combination (0-100):
- 40% — Task completion rate (0-40 points)
- 25% — Ticket burden (inverse: 0 tickets = 25, 10+ = 0)
- 20% — Activity recency (≤3 days = 20, 3-14 days = linear decay, >30 days = 0)
- 15% — Project update recency (≤7 days = 15, 7-30 days = decay, >60 days = 0)

Overall score → health:
- ≥80 → `green` — healthy
- 50-79 → `yellow` — at-risk
- <50 → `red` — critical

### R3: Client summary in response
Each health item includes client info (id, name, slug) and linked project count.

### R4: Empty state
Clients with no linked projects show "no projects" with N/A health (no score).

## 5. Data model

No new tables. Queries existing:
- `clients` — client list
- `project_clients` — project linkages
- `projects` — project status
- `tasks` — task completion
- `tickets` — ticket backlog
- `activities` — recent activity

---

## 6. APIs

| Method | Path | Description | Auth |
|--------|------|-------------|------|
| `GET` | `/v1/clients/health` | List clients with health metrics | Authenticated |

---

## 7. Invariants

- Health is computed at query time (no cached scores)
- Clients with 0 linked projects return `"health": null` and `"project_count": 0`
- Clients with linked projects but 0 tasks return 100% completion rate (vacuously true)
